# GEO 诊断闭环使用指南

## 概述

诊断闭环帮助用户系统性地评估品牌在 AI 对话平台上的可见度、引用情况和竞争位置，生成可执行的优化行动和复测机制。

## 四类诊断问题

| 类型 | 说明 | 建议数量 |
| --- | --- | ---: |
| 品牌问题 (BRAND) | 验证品牌能否被 AI 基本识别 | 3–5 |
| 品类问题 (CATEGORY) | 验证品牌能否进入品类推荐 | 5–10 |
| 场景问题 (SCENARIO) | 验证真实任务中能否被推荐 | 10–20 |
| 对比问题 (COMPARISON) | 验证与竞品比较时的位置 | 5–10 |

需要配置竞品后才能生成对比问题。

## 平台与采样

- 支持的平台：DeepSeek、豆包、通义千问、文心一言、Perplexity、ChatGPT Search、Gemini
- 每个平台需要配置独立的 API 凭证
- 采样次数 1–3 次，默认 2 次
- 请求总量 = Query 数 × 平台数 × 采样次数
- 单次运行上限 500 个执行单元

## 指标说明

### 有效样本率

`成功样本数 / 计划样本数`，衡量报告完整性。

### 品牌提及率

`品牌被提及的有效样本数 / 有效样本总数`，分别计算全局、Query 类型和平台维度。

### 品牌来源引用率

`官方来源被引用的样本数 / 有效样本总数`。没有品牌提及样本时返回无足够样本。

### 平均推荐排名

被提及且有排名的样本排名平均值。

### SOV (声量占比)

`品牌名称出现次数 / 品牌与竞品名称出现总次数`。SOV 依赖运行时竞品快照，不同竞品范围的运行不可严格比较。SOV 不可描述为真实市场份额。

### 报告可靠性

| 条件 | 可靠性 |
| --- | --- |
| 有效率 ≥ 90%，全部平台有效，运行完成 | 高 |
| 有效率 70%–89%，无平台完全缺失 | 中 |
| 有效率 < 70%，或任一平台完全缺失 | 低 |

部分完成的报告最高可靠性为"中"。

## 使用流程

1. **创建诊断项目**：录入品牌信息、目标用户、核心场景和竞品
2. **配置问题集**：生成、编辑、确认四类诊断问题
3. **创建诊断运行**：选择问题、平台和采样次数
4. **冻结并执行**：查看请求总量后开始执行
5. **查看报告**：获取六章诊断报告和发现
6. **执行行动**：接受、忽略或转换为优化任务
7. **复测**：复制基线范围再次诊断并比较结果

## 部分失败处理

- 单个平台失败不影响其他平台
- 自动重试最多 3 次（10 秒、30 秒、90 秒退避）
- 配置错误（凭证缺失、401）不自动重试
- 部分完成的运行可以手动重试失败样本

## 行动来源

行动由发现类型和 Query 类型确定性映射生成，不依赖 LLM 编造。

- **30 天**：修复品牌问题、补全来源引用、优化已有页面
- **60 天**：创建品类/场景/对比页面
- **90 天**：建设外部可信来源、调整内容矩阵

## 任务转换

支持转换为优化任务的操作：优化已有页面、重写内容、增加结构化数据、更新知识图谱。外部来源建设等行动为人工操作，首期不支持自动转换。

## 复测范围差异

复测默认复制基线范围。如果修改了 Query、平台或采样设置，报告标记为非严格可比，显示样本值差异而不宣称确定性提升。

## 常见错误

| 错误 | 处理方式 |
| --- | --- |
| 项目不存在 | 检查工作区切换或项目 ID |
| 无确认问题 | 至少确认一条诊断问题 |
| 平台未配置凭证 | 在设置页配置平台 API 凭证 |
| 超过 500 请求 | 减少 Query、平台或采样次数 |
| 队列不可用 | 诊断已保存，稍后重新派发 |
